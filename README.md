# Mobile App Starter - Flutter Pokédex

A modern Flutter application showcasing best practices for mobile development:
a Pokédex with infinite scroll, debounced search, persisted favourites and a
detail screen, built on BLoC with a clean layered architecture.

📐 **[ARCHITECTURE.md](ARCHITECTURE.md)** — why the project is shaped this way.
Read it before adding a feature; it covers the Bloc-vs-Cubit split, state
design, DI lifetimes, and a routing rule that fails *silently* if you miss it.

## 🚀 Features

- **State Management**: BLoC — `Cubit` for simple flows, event-driven `Bloc`
  with `EventTransformer`s where concurrency matters, sealed states with
  exhaustive `switch`, and a global `BlocObserver`
- **Infinite Scroll**: Pagination with parallel detail requests, bounded and cached
- **Debounced Search**: `bloc_concurrency` `restartable()` + debounce, so typing
  issues one request and stale results can never overwrite fresh ones
- **Favourites**: `HydratedBloc`, persisted across restarts, with `BlocSelector`
  so toggling one heart rebuilds one widget rather than the whole grid
- **Detail Screen**: typed route with a path parameter, Hero transition, and a
  route-scoped Cubit
- **Repository Layer**: `RepositoryProvider` between the blocs and the HTTP
  client, with a cached name index behind search
- **Dependency Injection**: Get_it for clean dependency management
- **Type-safe Routing**: go_router with code generation
- **Environment Configuration**: Multiple environment support (.env files)
- **Theming**: Material 3 with light/dark mode support
- **Error Handling**: Custom exceptions with graceful fallbacks
- **Localization**: Built-in `gen_l10n` with ARB files and type-safe getters
- **Network Layer**: Dio with custom error handling and logging
- **Code Generation**: build_runner for routes and JSON serialization
- **Performance Optimized**: Widget keys, const constructors, and efficient rebuilds
- **Design System**: `material_ui`, the standalone Material package split out of the SDK in Flutter 3.47
- **Tested**: 94 tests over the blocs, cubits, repository, HTTP client, DI container, router and UI
- **CI**: GitHub Actions runs `dart format --set-exit-if-changed`, `flutter analyze` and `flutter test` on every push and PR

## 🏗️ Architecture

The short version:

```
Widget  ──dispatch──▶  Bloc / Cubit  ──▶  Repository  ──▶  ClientAPI  ──▶  PokeAPI
   ▲                        │
   └────── State ───────────┘
```

- **`Cubit`** for plain commands (the list, the detail screen).
- **`Bloc`** where the *stream of inputs* needs transforming — search debounces
  and cancels in-flight requests via an `EventTransformer`.
- **Sealed states** consumed with exhaustive `switch`, so adding a state is a
  compile error rather than a blank screen.
- **All state lives in the state** — the cubits hold no mutable fields.
- **`RepositoryProvider`** between blocs and HTTP; `get_it` composes the graph
  at startup and only `main.dart` touches it.
- **`AppBlocObserver`** logs every bloc's lifecycle in debug.

**→ [ARCHITECTURE.md](ARCHITECTURE.md) explains the reasoning**, including why
each bloc widget was chosen, why every route must mix in `MaterialPageRouteData`,
how search works without a search endpoint, and the testing seams.


## 🔧 Setup and Installation

### Prerequisites
- Flutter SDK >= 3.47.0
- Dart SDK >= 3.13.0
- JDK 17-25 for Android builds. Gradle 9.3.1 does not support JDK 26, so point
  Flutter at Android Studio's bundled JBR:
  ```bash
  flutter config --jdk-dir="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
  ```
  To run `./gradlew` directly, also set `org.gradle.java.home` in your personal
  `~/.gradle/gradle.properties` (not in this repo — it is machine-specific).
- Xcode 27 and CocoaPods for iOS builds

### Installation Steps

1. **Clone the repository**
   ```bash
   git clone <repository-url>
   cd mobile_app_starter
   ```

2. **Install dependencies**
   ```bash
   flutter pub get
   ```

3. **Environment configuration — nothing to create**

   The three flavour files are tracked, so a fresh clone builds as-is:

   - `.env.dev` (default)
   - `.env.staging`
   - `.env.prod`

   Select one at run time:
   ```bash
   flutter run --dart-define=ENV_FILE=.env.staging
   ```

   **⚠️ Never put a secret in these files.** They ship as plaintext assets
   inside the APK/IPA and are extractable with `unzip`. Anything sensitive
   belongs in `--dart-define` values, which are compiled into the binary.

   Configuration is read through `AppConfig` (`lib/core/config/app_config.dart`),
   which is the single place that touches `dotenv`. A missing or malformed file
   does not crash the app — every key has a default.

4. **Generate code**
   ```bash
   flutter pub get                                            # also runs gen-l10n
   dart run build_runner build --delete-conflicting-outputs   # routes + JSON
   ```
   The two generators are independent: `gen_l10n` lives inside the Flutter
   tool and only reads `.arb` files, `build_runner` only reads annotated Dart.

5. **Run the app**
   ```bash
   flutter run
   ```

## 🎨 Theming

The app uses Material 3. Both schemes are built with `ColorScheme.fromSeed`,
then `copyWith` pins the brand colours:

- **Light Mode Primary**: #DC0A2D (Pokemon Red) — also the light seed
- **Light Mode Secondary**: #3B4CCA (Pokemon Blue)
- **Dark Mode Primary**: #FF1C1C (Lighter Red) — also the dark seed
- **Dark Mode Secondary**: #5B7BDB (Lighter Blue)

Seeding matters because widgets reach for roles nobody sets by hand
(`surfaceContainerHighest`, `onSurfaceVariant`); hand-writing four roles left
the other ~26 on Material's default palette, unrelated to these colours. One
`_base(ColorScheme)` builder produces both themes, so light and dark cannot
drift apart. Theme configuration is in `lib/core/themes/app_theme.dart`.

⚠️ `darkTheme` is wired into `MaterialApp` but nothing switches `themeMode`, so
only the OS setting can reach it. A theme cubit would be ~30 lines — see
[Known gaps](ARCHITECTURE.md#known-gaps).

## 🌐 Localization

The app uses Flutter's built-in `gen_l10n` — no third-party dependency.

- Strings live in `lib/l10n/app_<locale>.arb`; `lib/l10n/app_en.arb` is the
  template and every resource in it needs an `@`-description
  (`required-resource-attributes: true` in `l10n.yaml`).
- Add a language by dropping in `app_<locale>.arb`. It is picked up
  automatically — `supportedLocales` is derived from the filenames.
- Generation runs on `flutter pub get`, `flutter run` and `flutter build`. It
  does **not** run on `flutter analyze`, which is why the generated Dart is
  committed: a fresh clone would otherwise be a wall of red in the IDE.
- Call sites use `AppLocalizations.of(context).key`. The getter is
  non-nullable, so no `!` is needed.
- The locale follows the device. Server-provided error strings carried by
  `AppException` are intentionally *not* localized — see the comment on
  `AppException`. The generic fallbacks are: where there is no server message
  the bloc emits `null` and the widget layer substitutes `searchFailed` or
  `detailLoadFailed`.

## 📋 Code Guidelines

1. **Warning-Free Code**: `dart analyze` reports zero issues — keep it there
2. **Explicit Types**: `always_specify_types` is on, in `lib/` and `test/` alike
3. **Formatting**: width is pinned to 80 in `analysis_options.yaml`; run `dart format .`
4. **Named Parameters**: prefer them for anything with more than one argument
5. **Const Constructors**: use `const` wherever possible
6. **Widget Keys**: add keys to widgets in lists
7. **State Management**: business logic in blocs, never in widgets
8. **Error Handling**: use the `AppException` hierarchy, never swallow errors
9. **Theme Usage**: always use theme colors instead of hardcoded values
10. **Comments explain *why***: if a comment restates the line below it, delete it

See [ARCHITECTURE.md](ARCHITECTURE.md) for the conventions behind these.


## 🎯 Performance Best Practices

1. **Widget Keys**: All list items have `ValueKey` for efficient updates
2. **Const Constructors**: Static widgets use `const` to avoid rebuilds
3. **Lazy Loading**: Infinite scroll loads data progressively
4. **Bounded Parallel Calls**: detail requests for a page run concurrently, capped at 6 in flight, with repeats served from an in-memory cache
5. **Cached Name Index**: search filters a once-fetched index instead of hitting the network per keystroke; the ~1350-entry parse runs off the UI isolate
6. **Scoped Rebuilds**: `BlocSelector` means toggling one favourite rebuilds one button, not the grid
7. **Image Caching**: `CachedNetworkImage` with `memCacheWidth`, so the 475×475 artwork decodes at the rendered size
8. **Debounced Search**: one request per pause in typing, not per keystroke — and superseded requests are cancelled at the transport with `CancelToken`

## 🐛 Debugging

### Network Logging
In debug mode, all network requests are logged as CURL commands. Check the console for detailed request/response information.

### State Logging
`AppBlocObserver` logs bloc lifecycle events — creation, events, state changes
— for every bloc and cubit at once. Those are debug-only; **errors are logged
in every build**, since a release that discards them reports nothing at all:
```
[T] SearchBloc created
[I] PokemonCubit: PokemonInitial -> PokemonLoading
[I] PokemonCubit: PokemonLoading -> PokemonSuccess
[D] FavoritesBloc <- FavoriteToggled(25)
```

```bash
flutter pub global activate devtools
flutter pub global run devtools
```
